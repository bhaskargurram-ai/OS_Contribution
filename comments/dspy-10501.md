Thanks for the review — two of the three findings were real and are now fixed.

**Non-string keys.** The warning called `str.startswith` on every key in the store, so
`Example(base={1: "value"})` raised `AttributeError`. That works on `main`, so this branch
introduced it — I confirmed against a clean checkout before fixing. Only `str` keys can
collide with an attribute name, so the check now skips the rest.

**Repeated warnings.** The warning fired on every construction, and `copy()`, `without()`
and `with_inputs()` each build a new instance, so a legitimate field named `items` warned
on every one. It is now reported once per class and field name.

Tests added for both.

**`Prediction.completions`.** I left this one alone. Assigning to it diverging from the
read-only property getter is pre-existing behaviour around that property rather than
something this branch changes, and folding it in here would widen the PR past the issue.
Happy to open a separate issue for it if you'd like.
